# 版本追踪与回滚

记录现网与上一可用 Deployment ID、Git SHA、构建配置、域名、精确回调和审批记录。若出现数据隔离异常，应先限制受影响入口，保留脱敏诊断。

发布负责人批准后，在 Vercel Deployment History 选择已验收版本并核对 SHA，使用当前套餐支持的 Rollback 或 Promote 恢复到唯一生产别名。无可用旧部署时，以该 Git SHA 重新构建，遵循相同暂存和批准流程。若问题来自项目级保护、环境变量或 OAuth 注册，应分别检查这些设置的变更历史。

在旧标签页和全新浏览器分别打开正式根路径。检查新版本提示、入口缓存、JS/CSS/Worker、主题及图谱。完成一次回调与续期，验证账号与 Team 切换。回滚到未隔离本地配置的旧版本前，应限制共享浏览器使用并保留隔离版修复。记录恢复时间与实测结果，在 GitHub 通过 PR 修复或 revert。
